# /draft

One skill, two modes — auto-detected from the minutes file's presence and `status`. Write mode produces `status: drafted`; the GM bumps to `accepted` by hand after manual review. Audit mode preserves whatever status the file already carries — running it on `accepted` is a verification re-run, not a downgrade.

| State of `sessions/session-<NN>/minutes-<NN>.md` | Mode |
|---|---|
| File absent | **Write mode** — load context, draft, audit, stop. |
| File present, `status: drafted` | **Audit mode** — GM handoff, audit, canon updates. Status stays `drafted`. Idempotent. |
| File present, `status: accepted` | **Audit mode** — same flow against accepted canon. Status stays `accepted`. Any disposition or canon edit applied during the run modifies accepted artifacts in place — surface each edit to the GM as it happens. |
| File present, status missing or other value | Refuse with a clear error. |

The audit-mode runs MUST be invoked in a fresh conversation. The whole point of running them after the GM handoff is to catch bias the drafter introduces; that guard collapses if write-mode reasoning is still in context. Pass 3 (the trace-audit subagent) is context-isolated by construction and runs in both modes regardless.

## Required inputs (ask if missing)

- **Session number** (NN).
- **Session date** (YYYY-MM-DD, real-world) — write mode only. Use `xxxx-xx-xx` only if unrecoverable.
- **Transcript witnesses** at `sessions/session-<NN>/inputs/transcripts/`:
  - `transcript-<NN>.txt` — primary witness (canonical speaker labels).
  - `transcript-dia-<NN>.txt` — secondary witness (raw `SPEAKER_NN` labels).

  If both are missing, stop and tell the GM that `/transcribe`'s canonicalisation step hasn't run. Do not fall back to `raw/` or `external/`. Cross-reference rather than concatenate — treat them as multiple noisy witnesses of the same events.

  **Trust order.** The primary is canonical (names normalised, hallucinations filtered) — trust it for content, speaker, and timing; cite `transcript-<NN>.txt` line/time references by default. Use the secondary to corroborate or fill gaps; when committing a dia line, infer the speaker from content context (does the line reference that PC's spells / actions / backstory?) and discard the `SPEAKER_NN` tag.

## Write mode

### Before writing

Gather context before reading the transcript. The transcript is the noisiest source; prior canon is authoritative.

1. **Previous session files** (if N > 1) — `sessions/session-<N-1>/{gm,minutes}-<N-1>.md`. Establishes carryover and is the comparison target for triage *Prior-session audit*.
2. **Calendar notes** — `sessions/inputs/calendar.md` entries for the previous and current session. Source-note reliability flags are inline (parentheticals like *"GM post-session audio note, fully reliable"* / *"Gonzalo's resume unreliable"*). Reliable sources resolve transcript ambiguities directly; unreliable sources are hints to verify, not facts to commit.
3. **PC + NPC canon (digests)** — load `campaign/pcs/_context.md` + `campaign/npcs/_context.md`. Regenerated by `python3 .claude/skills/draft/_regen_context.py` — deterministic, zero-LLM, safe to run unconditionally if any source file was recently edited.
   - Use **public-generic descriptors** (*the goliath*, *the elf ranger*, *the dwarven castellan*) only when the matching `species` / `class` / `background` / `factions` / `gender` field is populated in the digest.
   - **`joined_at` filter** — exclude PCs whose `joined_at > <current session>` or is `null`.
   - **Consult `### Full sheet`** when a transcript-named spell/ability needs verifying — STT garbles spells routinely (*Fireball* and *Fire Bolt* sound identical in Spanish; *Goodberry* — Spanish *baya* — often renders as *valla*) — or when speaker attribution ties cleanly to one PC's exclusive list. A feature/spell not on the caster's list belongs in triage, not the minutes.
   - **NPC canonicalisation** — resolve transcript variants against `name` / `full_name` / `nicknames`.
   - **Source files as fallback** — read `campaign/{pcs,npcs}/<name>.md` only when the digest is missing a beat-critical field (subspecies, subclass, alignment, languages, source, full `## Concept` / `## Goal` / `## Current state` / `## Secrets`).
4. **Homebrew rules** — read every file in `campaign/homebrew/*.md`. These shape how transcript beats render.
5. **Transcript** — read carefully. STT quality is poor; flag genuinely confusing passages rather than invent. When N > 1, the **opening segment** (table-recap) feeds the triage *Prior-session audit*.
6. **In-fiction date references** — scan for DR year, Faerûnian month names, seasons, or *"hace X días/semanas"*. Surface what you find (or that nothing was found).

### Drafting

Draft minutes first, then triage (populated as items surface during minutes drafting). Set `status: drafted` as the first frontmatter field in `minutes-<NN>.md`.

#### `minutes-<NN>.md`

The standalone verified record of the whole session, in chronological order. Schema: [`sessions/templates/minutes-template.md`](../../../sessions/templates/minutes-template.md) — read it before drafting.

**Length target — 3–5 Homebrewery pages.** The minutes file should render to between 3 and 5 pages when built as a Homebrewery brew — under 3 misses beats the session earned; over 5 bloats the file with prose that no longer carries information. Recent accepted minutes as a working reference: S13 154 lines (~4 pages), S14 132 lines (~4 pages), S15 97 lines (~3 pages). Target **~100–180 lines of minutes body**; longer sessions get denser beats, not more beats. Trim style (verbose beat prose, atmospheric wordsmithing that doesn't carry a claim, adjacent micro-beats collapsible into one line) — never trim mechanically or narratively load-bearing content to hit the cap. If the draft comes in under 3 pages, walk the transcript again for beats the drafter compressed away rather than pad with atmosphere. Verify line count against the S13–S15 baseline before running the audit passes.

**EPIC tagging.** Proactively apply the `***[EPIC]***` prefix (template *EPIC TAG*) to beats you assess as peak heroic / dramatic / unforgettable — one-shot kills on tough enemies, defining monologues, near-TPK reversals, a duel's climactic round. Default: 2–6 per session, genuine peaks only. The GM removes unwanted ones during the manual review pass before bumping to `status: accepted`.

**Real-world end time.** When `sessions/inputs/calendar.md` records a start time but no end time, derive the end by adding the last transcript line's `[HH:MM:SS]` timestamp to the start (e.g., start 17:00 + transcript runs 03:39 → end 20:39). **Round the derived end to the nearest 10-minute segment** (20:39 → 20:40, 19:11 → 19:10) per the minutes template's `date` rule — the intent is a general sense of the session's shape, not clock precision. Write the rounded result **without** a trailing `?` (e.g., `date: 2025-03-16 17:00 - 20:40`) — per the template rule, real-world derived end times skip the TENTATIVE-VALUE MARKER because the 10-minute rounding is the fuzziness. Log the derivation in a triage *Date / continuity references* item showing both the raw calculation and the rounding step. If the calendar already records an end time, use that and skip the derivation.

#### `inputs/triage-<NN>.md`

Disposable workspace for items the GM clears once. Not canon. Schema: [`sessions/templates/triage-template.md`](../../../sessions/templates/triage-template.md) — read it before drafting.

### Write-mode audit

Once minutes + triage are written, run the same four audit passes audit mode runs (see [Audit passes](#audit-passes)). This is the in-context sanity layer — Pass 0 catches template-shape violations, Pass 1 and Pass 2 catch typos, format errors, obvious mis-attributions; Pass 3 (subagent) is the bias-isolated rigorous check.

Apply fixes inline. Pass 3 findings append to triage §9 — leave them for the GM (do not pre-filter the subagent's output).

Print a one-line status (files written + Pass 3 findings count) and stop. The GM will either bump straight to `status: accepted` (trusting the write-mode audit) or re-invoke `/draft <NN>` in a fresh conversation for the full audit-mode pass.

## Audit mode

Triggered automatically when minutes + triage already exist at `status: drafted` or `status: accepted`. Re-invocations are safe — work is idempotent. Status is preserved across the run.

**Citation-stripped accepted minutes.** Per the minutes template, files at `status: accepted` MAY carry no citations (the GM strips them during manual review). Pass 1 (transcript cross-check) and Pass 3 (trace-audit subagent) depend on per-claim citations and cannot run meaningfully without them. Detect at load: if `status: accepted` AND the minutes contain zero `[T:` / `[Td:` / `[derived:` / `[GM]` tags, skip Pass 1 and Pass 3 and tell the GM why — run only Pass 0 (shape) and Pass 2 (file-role / continuity / language). If citations are intact (the GM left them), run all four passes normally.

Sequence:

1. **Load context.** The two draft files; the transcript witnesses; `sessions/inputs/calendar.md` entries for current and previous session; the PC digest (`campaign/pcs/_context.md`) — small (~12 KB) and the canonical source for spell / feature / feat verification. Do **not** load homebrew, faction files, or location files — they shaped how write mode rendered beats; audit mode checks the rendered prose against the transcript, not whether it could have been rendered differently.
2. **GM handoff** — batched walkthrough at the end of the triage read. Skip any item already marked `[x]`. See [GM handoff](#gm-handoff).
3. **Apply dispositions** to the minutes (translate / drop Spanish quotes, fold STT canonicalisations, etc.). Close triage items.
4. **Audit passes 0 + 1 + 2 + 3** ([Audit passes](#audit-passes)) against the post-handoff minutes. Pass 2 re-run is implicit — it runs after dispositions are applied, against the final form.
5. **Canon updates** — walk triage §8 *File updates needed* with the GM per the [File updates inclusion rules](#file-updates-inclusion-rules). Auto-close items that clearly fail an exclude test (see the *Process at write mode and audit mode* subsection) so the GM sees the closure rather than another decision request; confirm the genuinely ambiguous ones; then apply downstream canon updates (PC `Current state`, `campaign/timeline.md` — see [Timeline inclusion rules](#timeline-inclusion-rules) — faction files, NPC files, location files, `sessions/inputs/calendar.md`). Use **create-if-missing** for any file that doesn't yet exist — these living canon files are maintained through this workflow, populated session-by-session. Do not auto-apply confirmed items without confirmation. **When creating a new NPC file: the filename stem must be `<given>-<surname>` (kebab-case, lowercase), matching `full_name` with any trailing epithet (`the Red`, `the Black`) stripped — never drop the surname. Verify against the sibling filenames in `campaign/npcs/` before writing.** Full rules in [`.claude/memory/feedback_npc_conventions.md`](../../memory/feedback_npc_conventions.md).
6. **Stop.** Status is preserved — `drafted` stays `drafted` (GM bumps to `accepted` by hand after manual review); `accepted` stays `accepted` (re-auditing accepted canon is a verification pass, not a downgrade). When the file was `accepted` going in, any disposition or canon edit applied during the run modifies accepted artifacts in place — surface each edit to the GM as it happens.

## GM handoff

Five batched items at the end of the triage read. Surface in priority order (P0 first):

1. **Unresolved triage flags.** Pass-3 findings (P1), STT canonicalisations, mechanical/rules flags, garbled passages. GM dispositions, AI applies.
2. **Date / continuity references.** Walk every anchor in §4 — both AI-resolved and still-open. Quote the GM's transcript words and the value derived. For derived anchors, show the calculation chain. The GM confirms `[x] confirmed` or `[x] revised: <new value>`; revisions propagate to frontmatter / scene headers. Then **scan the minutes prose for historical date / time / location riders** that aren't tied to a §4 anchor — *"during his Marpenoth-NN captivity"*, *"two days ago"*, *"at dawn"*, *"in the watch-cave"* embed inside beats without being surfaced as §4 anchors. Each rider must trace: to a transcript line on the host bullet, to `campaign/timeline.md` (cite as `[derived:timeline+T:...]`), or be dropped. Re-surface any unsupported rider as a new §4 anchor for GM disposition; do not silently fix.
3. **Named NPC file confirmation.** *"Named NPCs introduced or with significant changes: \<list\>. Which deserve a file in `campaign/npcs/`?"* Default suggestion: recurring / mission-givers / faction representatives = yes; one-scene cameos and stat-block mooks = no. Result populates the triage *File updates needed* section.
4. **Prior-session audit.** *"Players' opening recap surfaced these discrepancies with session N-1: \<list from triage *Prior-session audit*\>. For each: amend N-1's canon (you apply the edit manually), or close as player misremembering?"* When no discrepancies — or no recap detected, or N-1 canon missing — confirm the status item.
5. **Verbatim Spanish dispositions.** *"Every Spanish quote in the minutes draft, with my proposed disposition: \<list from triage *Verbatim Spanish dispositions*\>. For each: `keep` / `translate` / `drop`?"* The draft already reflects the proposals — confirmation pass. Apply: `translate` and `drop` strip the verbatim Spanish; `keep` leaves it. Close items `[x] kept` / `[x] translated` / `[x] dropped`.

EPIC tagging is owned by write mode; the GM removes unwanted EPIC tags during their manual review — audit mode doesn't touch them.

## Timeline inclusion rules

`campaign/timeline.md` is a lean chronological anchor of the campaign, not a per-session summary. Aim for **0–3 entries per session**; a single entry may span consecutive sessions when the in-fiction event is continuous (a multi-session travel leg, a multi-session dungeon delve resolved by one outcome).

**Include:**

- **Party location changes.** Travel from A to B, durable relocations (settlement, region, dungeon).
- **Named recurring NPCs.** First appearance, or a lasting change to one already known (freed, killed, allied with, betrayed by, revealed as X).
- **Character-defining PC events.** Death, resurrection, level milestone that unlocks a class-defining ability, life-goal completion, permanent injury or blessing, reputation shift.
- **EPIC moments.** The once-a-campaign scenes the table will remember years later: named duels, faction reveals, dragon reveals, major artifact acquisitions.

**Exclude:**

- Ephemeral encounters with no lasting consequence — road bandits, random skirmishes that don't change composition, location, or relationships.
- Session-level tactical detail — chest contents, trap triggers, spell/ability spends, combat blow-by-blow. That belongs in the minutes.
- Meta or pacing notes — *"cliffhanger into SN"*, *"party retreats to rest"*, *"session ended mid-combat"*, *"end of chapter N"*.
- Unresolved side-threads that later dissolve without narrative weight (revisit at the next canon update — promote only if they came back).

**Style:**

- **One short line per entry.** Short title clause plus a context clause; no bullet lists, no multiple sentences.
- **Bold named PCs, NPCs, and key artifacts** (`**name**`); nothing else gets emphasis.
- Neutral past tense. No editorial spin (*"a turning point"*, *"the strike is complete"*), no invention beyond what the minutes support.
- The event column is one cell; use `—` or `;` for internal punctuation, not line breaks.

**Atomic-event rows are dated to a single day, never a range:**

- Rule of thumb applies to the **row as a whole**, not to sub-clauses inside it. Look at what the row describes:
  - If the row's entire content is a **single moment** (a death, a duel, a dragon attack, a rescue, a resurrection, an NPC identification), the date is a single day. *Never* stretch it into a range to match a broader operation window.
  - If the row summarises a **genuinely multi-day operation** (a long travel leg, an extended camp / dungeon / siege activity, an ongoing negotiation), the date is a range. Atomic outcomes tied to that operation can be folded into the summary — the row is umbrella-shaped and the range describes the operation's duration.
- **One session can produce multiple rows.** Two distinct atomic events in the same session get separate rows (e.g., an NPC's death and a PC's death), each on its own date.
- **One event can span sessions.** A multi-day operation logged across S6–7 (or the same atomic event first recapped in one session and finished in the next) uses a session range in the Session column.

**Process during canon updates:**

- When walking triage §8, propose timeline additions only for beats matching the include list. Reject drafter-proposed additions that fail the exclude test — do not compromise by adding a shortened version.
- **Prefer extending an existing row over adding a new one** when the new session's material continues an in-fiction event already logged (a dungeon started in S6 and finished in S7 becomes one row spanning S6–7, not two).
- The GM confirms each addition and its wording before it lands in the file. Never auto-apply.

## File updates inclusion rules

Triage §8 (*File updates needed*) proposes edits to `campaign/{pcs,npcs,locations,factions}/*.md` — long-lived canon read out of session context. Load-bearing edits earn a bullet; session-scoped hospitality, one-off flavour, and expository colour do not — they already live in the minutes / gm files. GM has closed the same patterns as "not sheet-worthy" / "transient" across S13–S17 (representative: S15.1–3, S16.1–3 & 11, S17.8.5 sweet-wine / beer-thanks / warning-in-passing). Consult at both write-mode seeding and audit-mode handoff.

**PC `## Current state`** — full rules in [feedback_pc_conventions.md](../../memory/feedback_pc_conventions.md) (*no ephemeral state*). Include: new permanent items, key relationships, plot knowledge, trauma, open hooks, durable identity / faction shifts. Exclude: HP / wounds, consumables, magic-item charges, hours-duration effects, level / class-feature progression, anything that resets at a long rest — Foundry-tracked, not sheet-worthy.

**NPC `## Campaign notes`** — reference form: `26 Marpenoth 1489 (S9) — Killed in the Tiamat shrine.` Include: status changes (captured, killed, revived, freed, defected, sworn, identity revealed), party-relationship shifts (allied, hired, betrayed, refused), plot-critical exchanges (mission handed off, key intel delivered, plot item given / received), first appearance (only when promoting to a file). Exclude: hospitality and small talk (food, drink, meals, greetings, farewells, consumable gifts), one-off session flavour (warnings in passing, rumours repeated, local colour), expository lore delivery unless the *fact* is itself the beat, restating what the file already carries, passive re-appearances.

**Location files** — create-if-missing on first encounter with a named, geographically-distinct location that will plausibly recur. Update on: discovered features with lasting relevance, occupancy / control changes, named recurring NPCs stationed there. Exclude: per-visit combat and loot (minutes), unchanged details, passing-through-without-discovery, ad-hoc micro-locations.

**Faction files** — create-if-missing when named on-camera *and* carrying identifiable ideology + evidence of coordinated action or leadership. Update on: first presence in a new region, ideology / hierarchy reveals, named leadership changes, alliance / hostility with the party, lasting force-strength shifts. Exclude: individual mook encounters, uncorroborated rumours, supply-chain speculation (log the *lead* in gm §10 Secrets instead).

**Process.** *Write mode:* default to omit on borderline items — the beat still lives in the minutes; over-proposing wastes GM time at handoff. *Audit mode:* walk each §8 item against these rules before presenting; auto-close clear exclude-test failures as `[x] not sheet-worthy — <rule>` (e.g., `NPC-notes exclude: hospitality`) so the GM sees the closure, not another decision request. Present only genuinely ambiguous items and cite the include criterion you're proposing under.

## Audit passes

Same four passes whether invoked from write mode (in-context, post-draft) or audit mode (in-context, post-handoff). Pass 3 is always a subagent.

### Pass 0 — Template conformance

Walk the minutes file against the structural rules in the [minutes template](../../../sessions/templates/minutes-template.md). Don't auto-fix shape violations; surface findings as a numbered list and let the GM decide which to address. Most violations indicate GM hand-edits that broke template shape — the AI's defaults respect the template by construction.

Run before Pass 1 — if the shape is broken, the content checks can misalign (a malformed scene header confuses chronology grouping, a wrong citation tag misroutes the trace audit).

**Checks:**

- **Frontmatter** present, with all required fields: `status`, `date`, `in_fiction_date`, `party_present`, `party_absent`, `locations`. `status` is `drafted` (write mode output, or audit mode on a drafted file) or `accepted` (audit mode on accepted canon).
- **Frontmatter formats.** `date` is `YYYY-MM-DD` or `YYYY-MM-DD HH:MM - HH:MM` (with trailing `?` on derived end times). `in_fiction_date` uses FR calendar month names. `party_present`, `party_absent`, and `locations` are YAML block style (`-` per line, never `[a, b]` flow form, even single-item lists). `party_absent: none` literal when no PCs are absent.
- **H1 pair** matches `# Session NN {{float:"right" YYYY-MM-DD}}` followed on the next line by `{wide}`, where `NN` equals the session number and `YYYY-MM-DD` mirrors frontmatter `date`.
- **Scene headers** match `## N - <Title>` — bare integer, ASCII hyphen-minus, no "Scene" prefix. Scene numbers are 1-indexed and monotonic.
- **Date lines** (when present) match `_~HH:MM, DD <Month> YYYY DR_` with optional `~` (approximate) and `?` (derived) markers. Derived `?` markers cross-reference a triage *Date / continuity references* entry showing the calculation.
- **Beat numbering** restarts at 1 within each scene.
- **No blank lines between consecutive beats.** Beats within a scene sit one after another (the blank line appears only before the next scene header or the closing block). Auto-fix this one inline — it's a pure-formatting violation with no canon impact, and producing blank-separated beats is a recurring drafter habit.
- **EPIC tag** format: `***[EPIC]***` (exact triple-asterisks), placed immediately after the beat number.
- **Citation taxonomy.** Inline citations match `[T:N]`, `[T:N-M]`, `[Td:N]`, `[Td:N-M]`, `[GM]`, or `[derived:...]`. No other forms.
- **Tag-to-file mapping.** Every `[T:N]` resolves to a real line in `transcript-<NN>.txt`; every `[Td:N]` resolves to a real line in `transcript-dia-<NN>.txt`. (Pass 3 also runs this check; Pass 0 catches obvious malformations before the subagent spawns.)
- **Span width.** `[T:N-M]` spans typically ≤3 lines — flag wider spans as candidates for splitting (Pass 1 may further refine).
- **TENTATIVE-VALUE MARKER.** `?` appears on derived date/time components both in scene date lines and in frontmatter `date` / `in_fiction_date` where applicable.
- **Closing block** present at file end: `{{pageNumber,auto}}` then `{{footnote Tyranny of Dragons | Session <NN>}}` with `<NN>` matching the session number.

If all checks pass, log "Pass 0: clean." If findings surface, present them to the GM as a numbered list — these are shape violations to be addressed in the file directly, not triage items.

### Pass 1 — Transcript cross-check

Re-open the transcript files. For every claim in the minutes, find the supporting line or move it to triage as unresolved. **The trace is per-claim, not per-beat:** a beat carries several distinct factual claims (who acted, what they did, on whom, with what direction, at what location, with what outcome) and each one must trace independently. A beat is verified only when every claim inside it is verified — partial verification ("the action happened, even if the details are wrong") is not verification. This pass validates the per-claim citations described in the [minutes template](../../../sessions/templates/minutes-template.md).

**Categories of claim that have failed verification in past recaps — check each explicitly:**

- **Action attribution.** Transcript shows player A doing X → minutes credit player A. Failure mode in multi-actor rounds: the player who *succeeded* gets confused with one who *attempted* something similar.
- **Hit / miss / save outcomes.** Match the verb to the result. GM's *"entra"* / *"falla"* / *"no le doy"* / *"crítico"* drives whether prose renders a hit, miss, or crit. Failed save ≠ "the full hit" when half-damage on success was the actual outcome.
- **Movement direction.** Forward / backward / toward / away — pull the verb from the transcript. *"intenta avanzar"* (advances) is not "dashes back"; *"retrocede"* (retreats) is not "advances."
- **Character position and pairings.** Who carries whom, who is behind which cover. Re-check at each scene transition — pairings change mid-combat. Hiding ≠ immunity (render the actual fact: hidden, in cover, took or didn't take the damage).
- **Argument and stance.** When a player argues position X, the minutes do not render them arguing the opposite. For any beat paraphrasing a player's argument, identify the transcript line carrying the argument and check the direction.
- **Cast composition.** Who is on stage in a beat? Don't add enemies, allies, or witnesses absent from the transcript at that moment.
- **Spell name vs spell effect.** When prose renders a spell's effect, the prose must match what the spell actually does. *Emboldening Bond* (bonded buff granting d4) ≠ *"a small ring of warding light"* — match the spell's effect or use generic language that doesn't mis-describe it.
- **Spell, feature, and feat names mistranscribed by STT or attributed to the wrong PC.** Spanish speakers say *"Fireball"* and *"Fire Bolt"* near-identically; STT routinely conflates them. Class features (Action Surge, Sneak Attack, Rage, Lay on Hands, Wild Shape, Bardic Inspiration) are easy to mis-credit when several PCs are acting in the same beat. **Before committing or flagging, read the PC's `### Full sheet` block in `campaign/pcs/_context.md`**: Spells / Feats for spells; Class features / Species features for class / subclass / species abilities; Notable items for magic-item-granted effects. An ability granted by a feat (Magic Initiate, Ritual Caster), subclass / species, or magic item is valid even when absent from the base class list — "I checked the class list" is not sufficient. Only flag when genuinely absent from every block. Triage *Mechanical / rules flags* entries **must** cite the digest line range checked.
- **NPC names** — STT often garbles them; cross-reference NPC files (on demand) and prior sessions.
- **Dates, times, and locations.** Parenthetical riders inside otherwise-supported bullets — *"during his Marpenoth-16 captivity"*, *"at dawn"*, *"in the watch-cave"*, *"two days ago"* — attach a date / time / place to an action whose citation covers the action but not the rider. **This is the pipeline's highest-recall hole** (the dawn pattern; see [feedback_dawn_pattern.md](../../memory/feedback_dawn_pattern.md)). Decompose each bullet into atomic sub-claims; the date / time / location rider is its own sub-claim and traces separately. If the cited line(s) don't carry the date / time / location, anchor via `[derived:...]` (with the supporting calendar / timeline citation), `?`-flag to triage *Date / continuity references*, or drop the rider — never let it ride on the action citation. Softening the prose with hedges (*"perhaps during his earlier captivity"*) is not a resolution; dropping is.
- **Action declaration vs. outcome.** Player declarations (*"I attack X"*, *"I want to break Y"*) and the GM's acknowledgment of those declarations (*"yes, you swing"*, *"y me quieres dar un golpe que lo revienta, sí"*) are **not** outcome descriptions — they are evidence the action was *attempted*. The outcome is a separate transcript moment (the GM describing the result: *"the shell holds"*, *"the strike kills"*, *"el huevo no se ha roto"*) that may be lines or scenes away, or may be **visual / implicit at the table with no transcript line at all**. This is the egg pattern (see [feedback_egg_pattern.md](../../memory/feedback_egg_pattern.md)) — the S9 *cracks the egg open* claim cited T:3933 (an acknowledgment-of-intent line), never had an outcome line, propagated through three audit passes and into delivered minutes / saga / GM. For every bullet using an outcome verb (*cracks, kills, destroys, opens, captures, wounds, drops, breaks, shatters, slays, beheads, dies, falls* in the "drops to 0 HP" sense, *flees* in the "successfully escapes" sense), classify each cited line as **(D)** player declaration, **(A)** GM acknowledgment of intent, or **(O)** GM outcome description; the bullet's verb must rest on at least one (O). If only (D) / (A) lines exist in range and no (O) line is findable elsewhere in the transcript, either re-word to **attempt-language** (*"strikes at"*, *"swings at"*, *"tries to break"*) or `?`-flag the bullet for GM resolution at handoff (visual / implicit outcomes are legitimate but must be GM-confirmed, never assumed by the drafter). The check is non-negotiable for consequential outcomes (death, destruction, key item state changes); for those, the (O) line or a GM confirmation is required — attempt-language is not enough.
- **Sequencing** — walk the transcript chronologically. A beat described in one place that actually occurred elsewhere is a chronology error.
- **Atmospheric / flavour prose.** Phrases like *"the dawn comes thin and cold"*, *"gear smoking"*, *"slings over a shoulder"* (when the transcript shows dragging) assert facts about the scene. Each must trace. Wordsmithing existing transcript beats is permitted; inventing atmospheric facts is not.
- **Inferred details.** An inference is a load-bearing claim — every downstream beat that depends on it inherits its un-traceability. The inference must be marked (`?` in scene tags, an entry in triage *Date / continuity references*, or a `[derived:...]` citation); verify the markings exist and the cascade was respected.

**For any claim that cannot be anchored to a single direct transcript line, walk the citation cascade** in the [minutes template](../../../sessions/templates/minutes-template.md) — `[T:N]`/`[Td:N]` → `[derived:T:N1+T:N2+...]` → `?`-flagged to the triage *Date / continuity references* or *Derived beats* section → drop. **Drop is the last resort, not the default.** Silently cutting a beat fragments the minutes' narrative spine and breaks the *Completeness* principle just as badly as inventing content breaks *Traceability*. Hedging in the prose ("possibly," "presumably," "the party may have…") is not permitted — unverified content is anchored via `[derived:...]` or `?`-flagged to triage, never softened into ambiguous prose.

**Triage §8 (File updates needed) gets the same per-claim trace as the minutes.** Drafter inventions tend to seed §8 PC current-state and NPC campaign-note bullets at the same time they seed a minutes beat — once a fabrication lands in three places (minutes + §8 PC state + §8 NPC note), any auditor scanning one of them sees confirmation against the others rather than contradiction. Walk §8 line by line: every date, name, action, and quoted phrase must trace to a transcript line or to an explicit `[derived:...]` chain that itself resolves. §8 entries don't carry inline citations in the template (they're operational notes the GM applies manually to canon files), but they're audited against the transcript the same way — flag any unsupported claim back to triage so the GM doesn't carry the fabrication into `campaign/{state,timeline,pcs,npcs,locations,factions}/*.md`. **Also apply the [File updates inclusion rules](#file-updates-inclusion-rules)** — traceable-but-trivial bullets (hospitality, one-off flavour, expository colour, ephemeral PC state) drop out here, not at the GM handoff.

### Pass 2 — File-role check

Read each file as its consumer.

- **Minutes — per-beat check.** Every beat traceable, colour and mechanical detail preserved, chronological. No editorialisation.
- **Minutes — continuity spine.** Walk the file top-to-bottom as a reader. Track each character's state across the session — alive / wounded / unconscious / carried, location, what they hold, who they're with. When state changes between adjacent beats, a beat must *cause* the change: a recovery before walking, a carrier beat before being moved, a transit between locations, an acquisition before an item appears in hand. **This is the only pass that surfaces content *missing* from the draft.** When a gap surfaces, return to the transcript and re-derive through the cascade — never paper over the gap with editorial smoothing, and never leave it unflagged. Failure mode: the minutes read smoothly enough that gaps don't trip the reader's own ear — only the GM who was there spots them. Treat this pass as the gap-detector the trace audit cannot be (the audit walks bullets that exist; it can't see beats that should be there and aren't).
- **Triage.** Every item is actionable or a flag the GM must resolve. Nothing decorative.
- **Cast naming.** Allowed references: character name, full name (per frontmatter), nicknames (per the `nicknames` field), or a public generic descriptor — species / class / background. **Each descriptor only counts as permitted if the corresponding field is populated in the file.** Never use anything from a PC's *Secrets* section. Load PC/NPC file frontmatter on demand to verify.
- **Natural language.** "kobolds and cultists", not "kobolds + cultists"; never `+` / `/` / `&` between coordinated nouns outside time ranges or scene.beat coordinates.
- **No unquoted Spanish in narrative prose.** Scan for Spanish words sitting in English narration outside quotes — *meseta*, *barranco*, *ladera*, *bastión*, *chamán*, *fémur*, *aldea*, *hermanos de sangre* — translate (*plateau*, *ravine*, *slope*, *keep*, *shaman*, *femur*, *village*, *blood brothers*) unless inside verbatim quotes or canon proper nouns from `campaign/{pcs,npcs,locations}/*.md`. British English throughout (organise, recognise, armour, honour, centre); never American. Self-check: would a monolingual English reader stumble? If yes, translate.
- **Mechanics scrubbing.** Per the minutes template's *PROSE STYLE* rule, mechanics jargon does not belong in the prose. This is a *token-level* scan, not a vibes-read — drafters drift toward rules language when transcribing combat and the audit must actively grep for it. **The right axis is *invocation framing*, not vocabulary.** The fix is to render the in-fiction effect, not to thesaurus-swap — *Rage → Fury*, *Sleep → Slumber*, *cast → weaves* are wrong moves: the output reads stilted and the rules invocation is still there in a costume. Many 5e feature and spell names are plain English words that predate the rulebook (*rage, fury, sleep, haste, bless, shield, fire, light, silence, fly, heal*) and the verb *cast* is natural English for throwing a spell / line / net — in natural prose, these STAY. The scan guards against the shape *"X uses / activates / triggers <Rules Thing>"*, not against the words themselves.

  Two-step pass:
  1. **Emphasis-markup tell** (high-precision). Grep for `*<term>*` and `**<term>**`. A mechanics term wrapped in italics or bold (`*critical*`, `**critical**`, `*Incapacitated*`, `*bloodied*`, `*maximum damage*`) is the prose invoking the rules entry as a marker. Always strip the markup and render the in-fiction effect — emphasised mechanical terms are never natural English.
  2. **Token list** (regardless of emphasis). Scan for each term below; apply the template's *Proper-noun recognisability test* (would a 5e-experienced reader cross-reference to a rules entry?) and render-as-effect when yes. **Default to KEEP** — flag only when the surrounding prose makes the rules invocation unambiguous (capitalised proper-noun form, *"uses X"* / *"activates X"* / *"triggers X"* framing, mechanical-outcome scaffolding around it).
     - **Class / subclass / species features**: *Action Surge*, *Second Wind*, *Cloud's Jaunt*, *Pack Tactics*, *Multi-Attack*, *Sneak Attack*, *Wild Shape*, *Bardic Inspiration*, *Lay on Hands*, *Channel Divinity*, *Reckless Attack*, *Dread Ambusher*, *Rage* — and any feature listed in a PC's `### Full sheet → Class features` / `Species features` block in `campaign/pcs/_context.md`. Lowercase common-English hits of the same tokens (*"he rages at the doorway"*) are not rules invocations and stay.
     - **Spell names** in narrative position: cross-reference `### Full sheet → Spells`. Flag only when the name is invoked as rules-marker (*"casts Sleep on them"*, *"Fireball goes off"*). The verb *cast* on its own is plain English — "casts a sphere of radiant light" is fine. When the beat hinges on the name itself (a named-spell taunt, a verbal component dramatised by the GM), the name stands.
     - **Action-economy jargon** (no plain-English use): *cantrip*, *spell slot*, *bonus action*, *reaction* (as a noun — "the reaction she had set up"), *opportunity attack*, *saving throw*, *advantage*, *disadvantage*, *attack roll*, *ability check*, *skill check*, *initiative*, *hit dice*, *temporary HP*, *hit points*, *HP*, *AC*, *DC*.
     - **Combat outcomes**: *critical* (when emphasised or read as marker), *maximum damage*, *half damage*, *double damage*.
     - **Conditions** (when emphasised, or obviously mechanical to a lay reader): *incapacitated*, *bloodied*, *restrained*, *prone*, *frightened*, *charmed*, *stunned*, *paralysed*, *grappled*. Plain-English use of the same words (*"she goes prone to crawl under the ledge"*, *"he grapples the frog by the neck"*) stays.
     - **Grid / dice references**: *squares* (grid), *five-foot step*, *long range*, *"rolls a 20"*, *"rolls high"*, *movement halved*, *speed reduced*, *30 feet* (when invoking a rules range rather than describing a real distance).

  Keep common English that overlaps with mechanics — *party, dash, rest, damage, attack, hit, miss, save* (verb), *cover, roar, cast, rage, sleep, haste, shield, fire, light, fly, heal, bless, silence*. **The thesaurus test** — if the only reason to swap a word is that it looks like a rules term, don't swap it. Over-correction reads stilted; under-correction leaves rules invocations in the prose.

- **OOC and meta-narration scrubbing.** The minutes narrate what happened *in fiction*; GM table-direction and player-side activity are explicitly out of scope (minutes template EXCLUDED: *"Out-of-character table activity … Only what happened IN FICTION"*). Two-step scan parallel to mechanics scrubbing:
  1. **Out-of-fiction tokens.** Grep for: *GM*, *DM*, *the table*, *the player*, *the players*, *Foundry*, *PC*, *NPC*, *"in initiative"*, *"in combat"* used as a phase marker rather than a description. **`GM` is the project idiom** — a `GM`-less token list lets every GM reference through, which is how the S38 beats shipped.
  2. **GM-narrates patterns.** Grep for *"the GM"* / *"the DM"* followed by any of: *resets, confirms, warns, says, narrates, describes, rules, calls, announces, allows, names, tells, clarifies, adjudicates*. These are the drafter paraphrasing table-direction into the beat. Re-render as the in-fiction event (what the characters perceive and do), or drop if the beat is purely procedural — *"the GM resets the scene before play"* carries no in-fiction content; cut it. Also catch *"nickname at the table"*, *"has to leave the table"*, *"at the table"* used as a sidebar — player-side references that belong in triage or nowhere. **The S38 pattern** — *"The GM resets the scene"*, *"the GM confirms the sage is already finished"*, *"the GM warns them he will"*, *"Harley, by the nickname at the table"*, *"Nyx has to leave the table"* — is this category end-to-end.

- **Numeric dice results and round-counts.** Minutes template EXCLUDED forbids *"to-hit totals, damage, HP, AC, save DCs, roll values"* and turn-by-turn combat sequencing. Two token-level scans:
  1. **Numeric roll-value tokens.** Grep for digit and spelled-out numbers adjacent to any of: *points*, *damage*, *HP*, *AC*, *save*, *DC*, *hit dice*, *to-hit*. Flag *"twenty points from his hit dice"*, *"ten points of damage"*. Re-render as narrative outcome (*"closes two of them with the last of his short rest"*). **Keep real-world distances** (walking distances, bowshots in feet or paces when describing a real physical gap), **counts of boats, people, arrows, spears, enemies**, resource counts (gold, potions, ammo), explicit awards — these are not dice results. The *feet* unit is only a rules reference when it's clearly a mechanic (jump distance expressed as a grid range, spell range) — a physical description of a climb or a shot stays.
  2. **Round / turn / initiative tokens.** Grep for *rounds*, *took N rounds*, *across many rounds*, *turn* (combat-timing sense), *initiative order*, *on his turn*, *on her next turn*. These are metagaming time-markers; combat already flows chronologically in the prose. Re-render as in-fiction duration (*"across the long back-and-forth"*, *"between swings"*, *"as the second mage climbed through the slit"*). **The S38 pattern** — *"Across many rounds the party drops…"*, *"The whole fight has taken ten rounds"* — is this category.
- **Date / time / location / atmospheric scan.** Token-level grep, not vibes-read — the dawn pattern repeated across S6 / S7 / S9 because each pass deferred to *"the citation broadly covers the bullet"* and this scan was never made mechanical. Three sub-scans, each high-precision:
  1. **Faerûnian calendar tokens.** Grep for *Hammer, Alturiak, Ches, Tarsakh, Mirtul, Kythorn, Flamerule, Eleasis, Eleint, Marpenoth, Uktar, Nightal* and any `NN <Month>` / `<Month>-NN` / `<Month> NN` numeric date form. For each hit not in frontmatter / a scene date line / a dispositioned §4 anchor, verify the host bullet's citation **actually carries the date** — not just the surrounding action. If absent, the rider is a Pass 1 *Dates, times, and locations* failure surfaced too late; re-anchor via `[derived:...]` or drop. This is the check that would have caught the S9 *Marpenoth-16* rider.
  2. **Time-of-day and atmospheric tokens.** Grep for *dawn, dusk, twilight, midnight, midday, noon, evening, morning, night-fall, sunrise, sunset, daybreak, first light, last light* and for weather / light phrases (*in the dark, by torchlight, under cloud, in the rain, cold light, thin light*). Same verification — the rider traces to the cited line, not to the bullet's main claim.
  3. **In-fiction location tokens.** Grep for proper-noun location names (filenames under `campaign/locations/*.md`) and scene-local descriptors (*the watch-cave, the outer chamber, the upper barracks, the columned chamber, the river-bend*). The host bullet's citation must place the action there; *"in the X"* added to a transcript-supported action that doesn't itself name a location is a rider.

  For each flagged rider: prefer re-anchor (cite the calendar / timeline / transcript line that does support it) over drop; never paper over with a hedge.
- **Outcome-verb scan.** Token-level grep for outcome verbs in active voice that claim consequential state change: *kill / kills / killed, slay / slays / slain, behead / beheaded, dies / died, drops* (in the "to 0 HP" sense), *break / breaks / broke / broken, crack / cracks / cracked / cracked open, shatter / shatters / shattered, smash / smashes / smashed, destroy / destroys / destroyed, open / opens / opened* (an obstacle, container, or door, when the bullet hinges on the breach), *captures / captured, frees / freed, escapes / escaped, flees / fled* (in the "successfully evaded" sense), *wounds / wounded* (when claiming a specific lasting injury). For each hit, walk the citation by role-type per Pass 1's *Action declaration vs. outcome*: classify each cited line as (D) / (A) / (O), and verify at least one (O) line backs the verb. If absent and no (O) line is findable: re-word to attempt-language, **or** `?`-flag for GM at handoff. **This is the check that would have caught the S9 *cracks the egg open* claim** — cited to T:3933, an (A) line; no (O) line existed in transcript 9 because the egg shell never broke. See [feedback_egg_pattern.md](../../memory/feedback_egg_pattern.md).

Apply fixes, then run Pass 3.

### Pass 3 — Independent trace audit (mandatory, always)

Spawn the **trace-audit subagent** in its own isolated context. It has no draft history and no review-pass history — it sees only its inputs.

Spawn via the Agent tool with `subagent_type: "trace-audit"`. Pass through:

- Session number `<NN>`.
- The transcript file(s) available — `sessions/session-<NN>/inputs/transcripts/transcript-<NN>.txt` and/or `transcript-dia-<NN>.txt`.
- `sessions/session-<NN>/minutes-<NN>.md`.
- `sessions/session-<NN>/inputs/triage-<NN>.md`.

The subagent walks every minutes bullet, verifies each citation resolves to its declared file and supports its claim, runs the per-file non-decreasing chronology check, applies `?ord` markers inline to chronologically suspect citations, and appends a `## 9. Trace audit` section to triage with one P1 item per finding. You do not pre-audit, filter, or edit the subagent's findings — its isolation is the point.

In audit mode, if §9 already exists from a previous run, the subagent replaces (not appends) it — re-runs produce a fresh report against the current state of the minutes.

## Snapshot

The first time write mode runs (no minutes file existed beforehand), snapshot the post-Pass-3 minutes to `sessions/session-<NN>/inputs/minutes-<NN>.draft.md`. Forensic baseline — subsequent GM edits and audit-mode runs can be diffed against it.

The snapshot is **only overwritten when the live minutes file is freshly regenerated** by write mode (file didn't pre-exist, or the GM deleted it to force a fresh run). Audit-mode runs and GM edits never overwrite the snapshot — it represents *the version the AI first handed off after generation*.
