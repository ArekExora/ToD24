This is a personal GM toolkit, not a production system with deadlines. There are no time constraints on individual tasks — taking longer is acceptable (and preferred) if it produces higher-quality output.

**Why:** The user explicitly stated this as a general rule when deciding to add a third review pass to `/saga`. The recap pipeline's value is in the quality of the artifacts it produces (player recaps that read as proper saga prose, GM logs that are accurate canon), not in how fast they're generated.

**How to apply:**
- When proposing a tradeoff between thoroughness and speed (e.g., "lighter touch" vs. "cleaner split", one review pass vs. multiple, condensed analysis vs. fuller diagnosis), default to the higher-quality option unless the user signals otherwise.
- Don't compress review passes, skill instructions, or analysis to "save time" — the user would rather wait for a better result.
- When a task has natural quality-improving extensions (extra verification, additional cross-checks, more careful prose), proposing them is welcome.
- This is not a license to over-engineer or add unnecessary scope. The bar is *quality of the requested task*, not *expanding the task*.
